How K-Means Clustering Works Here: Every job title and description is converted into a TF-IDF vector — a numerical representation where each dimension is a word and its value reflects how important that word is relative to all jobs. K-Means then groups jobs by minimising the distance between each job and its cluster centroid. The result reveals natural groupings in the job market without any predefined labels.

Linear Regression Salary Model: We train a Linear Regression model on jobs that have salary data. Each job is represented as a one-hot encoded vector of its industry and location — the regression learns a coefficient (weight) for each feature that captures how much that industry or location shifts the predicted salary up or down from the intercept. The model predicts a continuous dollar value, not a bucket. Evaluated with R² (how much variance is explained) and MAE (average dollar error) via cross-validation.

How the Matching Model Works

Step 1 — Resume Parsing (Gemini 2.5 Flash): The uploaded PDF is extracted to plain text using pypdf. The text is sent to Gemini with a structured prompt requesting JSON output: skills, job titles, experience level, education, and 5–8 tailored Adzuna search queries.

Step 2 — Job Fetching (Adzuna API): Each Gemini-generated query is sent to Adzuna's search endpoint (api.adzuna.com/v1/api/jobs/us/search) with results_per_page=50. Results are filtered by a regex that removes senior-level titles (senior, lead, manager, director, VP, etc.) using word boundaries.

Step 3 — Keyword Matching Score: Each job is scored by counting how many of the candidate's extracted skills and target job titles appear in the job's combined text (title + company + description + industry). Raw overlap (0–1) is normalised to 80–99% since all results are already contextually relevant.

Step 4 — Ranking: Jobs are sorted by match score descending and returned to the frontend. Filters (location, industry, visa sponsorship, search) run as SQL ILIKE queries server-side before scoring.
